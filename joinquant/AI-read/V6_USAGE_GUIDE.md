## 🔑 核心改进点

### 1. 质量优先（vs v5的致命错误）

**v6保留严格质量筛选：**
```python
# line 281-288: 质量要求
income.net_profit > 0,           # 必须盈利
indicator.roe > 0.05,            # ROE>5%（质量门槛）
income.operating_revenue > 5e7   # 营收>5000万（避免空壳）
valuation.market_cap >= 8        # 8亿起（避开垃圾股区）
```

**v5的错误（已修正）：**
```python
# ❌ v5只要求盈利，无ROE/营收要求
# ❌ 市值5亿起，进入垃圾股重灾区
# ❌ 选股200支，质量参差不齐
```

### 2. 适度进攻（vs v2的保守）

**仓位提升：60% → 70%**
- v2: 60%小市值 + 40% ETF（稳健）
- v6: 70%小市值 + 30% ETF（适度进攻）
- 理论收益提升：+15%

**持股增加：4只 → 6只**
- 更多优质标的机会
- 单只仓位：11.7%（70%/6）
- 仍保持集中度优势

**选股范围扩大：10-100亿 → 8-120亿**
- 略扩大候选池
- 但避开5-10亿垃圾区

### 3. 严格风控（v2标准）

**止损：9%（不是v5的12%）**
```python
g.stop_loss_ratio = 0.09  # 单只最多亏1.05%（9%×11.7%）
```

**止盈：150%（不是v5的300%）**
```python
g.stop_profit_ratio = 1.50  # 现实可达目标
```

**移动止损：收益>30%后启动**
```python
# 从最高点回撤25%时卖出
if pft < max_pft * 0.75:
    sell()
```

### 4. 稳健节奏（v2经验）

**调仓频率：每周二（不是v5暗示的每日）**
```python
run_weekly(rebalance_small_cap, 2, '9:35')
```

**原因：**
- 降低交易成本
- 给优质股成长时间
- v2验证有效

## ⚠️ 风险提示

### 可能出现的问题

**1. 收益低于预期（60-80%）**

**原因：**
- 市场环境不利小市值
- 选股条件过严
- ETF拖累

**解决：**
```python
# 可适度放宽（但保持质量！）
g.small_cap_ratio = 0.75  # 70%→75%
g.max_market_cap = 130    # 120→130亿
```

**2. 回撤超过10%**

**原因：**
- 市场暴跌
- 指数熔断未及时触发
- 止损太宽

**解决：**
```python
# 收紧风控
g.stop_loss_ratio = 0.08  # 9%→8%
g.max_drawdown_limit = 0.09  # 10%→9%
g.index_crash_threshold = 0.04  # 5%→4%
```

**3. 交易过少（<50笔/年）**

**原因：**
- 选股太严格
- 股票池太小

**解决：**
```python
# 略放宽条件
indicator.roe > 0.03  # 5%→3%
income.operating_revenue > 3e7  # 5000万→3000万
```
